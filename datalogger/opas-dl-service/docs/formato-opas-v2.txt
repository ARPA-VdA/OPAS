➤ NOME FILE:
    Per formare il nome del file bisogna unire l "Header file dati" impostato nella configurazione ed una data.

    FILE-HEADER-YYYY-MM-DD-HH-MM-00.dat (
            Esempio: ao_plouves-2022-08-01-07-00-00.dat, ao_plouves-2023-03-03-16-00-00.dat
                     è possibile inserire una data fittizia per evitare di sovrascrivere il file al centro
                     ao_plouves-2023-03-03-16-00-01.dat - 01 secondi
        )

    FILE-HEADER Deve essere univoco nella rete

    NB: La data del file non viene utilizzate per marcare i dati, ha il solo scopo di organirrare i file per data


➤ CAMPI:
    DATA + ORA -> Data ora media targata anticipata (0 - 23) e ora solare. Es: 2022-08-01 06:00:00 Media dei dati dalle 06:00:00 alle 06:59:59
    ID         -> Id univoco del parametro corrispondente allid del database. In caso di una nuova stazione possono essere progressivi da 1
    VAL        -> Valore della misura
    P.COD      -> Codice stato misura (0=valido)
    S.COD      -> Codice stato stazione (0=nessun allarme)
    PERC       -> Percentuale di dati validi nellora
    MIN        -> Valore minimo (vuoto se non disponibile)
    H.MIN      -> Ora minuti e secondi del valore minimo (06:38:15) 00:00:00 se non disponibile
    MAX        -> Valore massimo (vuoto se non disponibile)
    H.MAX      -> Ora minuti e secondi del valore massimo (06:25:14) 00:00:00 se non disponibile
    STDDEV     -> Deviazione standard (0 se non disponibile)

➤ FILE
DATA + ORA           ID  VAL  P.COD  S.COD  PERC  MIN   H.MIN      MAX   H.MAX      STDDEV
2022-08-01 06:00:00, 1,  3.5, 0,     0,     100,  2.1,  06:38:15,  8.2,  06:25:14,  1.6
2023-03-03 16:00:00, 1,  3.5, 0,     0,     100,     ,  00:00:00,     ,  00:00:00,  1.6


♦ Esempio file (NON deve contenere spazi):
2022-08-01 06:00:00,1,3.5,0,0,100,2.1,06:38:15,8.2,06:25:14,1.6
2022-08-01 06:00:00,2,0.8,0,0,100,0.1,06:37:55,1.4,06:09:22,0.3
2022-08-01 06:00:00,3,2.7,0,0,100,1.5,06:09:02,6.9,06:25:14,1.4
2023-03-03 11:00:00,1,,128,1,0,,00:00:00,,00:00:00,0


Il file può contenere qualsiasi data nel suo interno, non cè correlazione tra la data del file ed il contenuto
Se lo stesso dato (ora + id parametro) viene re-inviato, non viene inserito nel database,
per cui non viene aggiornato il vecchio record.


Regular expression per validare il record:
    \d{4}-\d{2}-\d{2}\s\d{2}\:\d{2}\:\d{2},\d+,
    ((-|\+)?\d*(.\d+)?),\d+,\d+,\d+,((-|\+)?\d*(.\d+)?),\d{2}\:\d{2}\:\d{2}\,
    ((-|\+)?\d*(.\d+)?),\d{2}\:\d{2}\:\d{2}\,((-|\+)?\d*(.\d+)?)


Codice stato misura

DL         | Descrizione
-----------+------------------------------------------------------------------------
0          | Valido
1          | Valore dello Span minore del limite calcolato in base alla tolleranza
2          | Valore dello Span maggiore del limite calcolato in base alla tolleranza
4          | Valore dello Zero minore del limite calcolato in base alla tolleranza
8          | Valore dello Zero maggiore del limite calcolato in base alla tolleranza
16         | Taratura
32         | Manutenzione Ordinaria
64         | Manutenzione Straordinaria
128        | Misura non valida causa numero di letture inferiore al 75% di copertura
256        | Errore dello strumento letto dal flag di status
512        | Misura compresa tra + e – detection limit
1024       | Misura inferiore a - detection limit
2048       | Misura istantanea inferiore al minimo ammesso
4096       | Misura istantanea superiore al massimo ammesso
8192       | Misura istantanea oltre la variazione ammessa


Codice stato stazione

DL         | Descrizione
-----------+------------------------------------------------------------------------
0          | Situazione normale e funzionante, senza anomalie
1          | Errore generico software
2          | Riavvio del sistema
4          | Spazio su disco in esaurimento
